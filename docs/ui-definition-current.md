## 1. 대시보드 > 대시보드 (DA-M01)

- 업무 레벨 1: 대시보드
- 업무 레벨 2: 대시보드
- 화면 유형: 메인 화면
- 화면 ID: DA-M01
- 화면명: 대시보드
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: 프로젝트의 RTM 충족 현황, PASS율 추이, 연결 파일, 최근 실행 이력을 요약해 보여준다.

### 화면 구성

- 상단 탭: `Overview`, `People`, `Settings`
- RTM 도넛 차트: 충족, 미충족, 미측정 건수 및 전체 건수 표시
- PASS율 추이 차트: `PassRateChart` 컴포넌트 표시
- FILES 영역: 연결 파일 목록 및 시나리오 반영 상태 표시
- 이력 영역: 최근 테스트 실행 이력 목록 표시

### 처리절차

- 사용자가 좌측 내비게이션에서 `HOME`을 선택하면 대시보드 화면을 표시한다.
- `Overview` 탭 선택 시 RTM 요약, PASS율 추이, 연결 파일, 최근 이력을 표시한다.
- 이력 행을 클릭하면 테스트 화면으로 이동한다.
- `People`, `Settings` 탭 선택 시 각 탭 화면으로 전환한다.

### 제약사항

- RTM 충족률, PASS율, 최근 실행 이력은 동일 기준 시점의 데이터로 집계돼야 한다.
- 대시보드 지표는 사용자가 접근 권한을 가진 프로젝트 데이터만 포함해야 한다.
- 최근 실행 이력 클릭 시 연결되는 테스트 정보는 해당 실행 ID와 일관돼야 한다.

## 2. 대시보드 > 멤버 관리 (DA-M02)

- 업무 레벨 1: 대시보드
- 업무 레벨 2: 멤버 관리
- 화면 유형: 탭 화면
- 화면 ID: DA-M02
- 화면명: 멤버 관리
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: 대시보드 내 프로젝트 멤버를 검색, 선택, 초대, 내보내기 할 수 있는 멤버 관리 탭이다.

### 화면 구성

- 진입 위치: 대시보드 상단 `People` 탭
- 상단 도구 영역: 멤버 검색, `내보내기`, `멤버 초대`
- 멤버 테이블: 전체 선택 체크박스, 멤버, 2FA, 역할, 팀, 추가 메뉴
- 멤버 행: 아바타 이니셜, 이름, 사용자명, 소속 방식, 2FA 아이콘, 역할 배지, 팀 수

### 처리절차

- 사용자가 대시보드에서 `People` 탭을 선택한다.
- 검색어 입력 시 멤버 이름 또는 사용자명 기준으로 목록을 필터링한다.
- 전체 선택 체크박스 선택 시 현재 표시된 멤버 전체 선택 상태를 토글한다.
- 개별 멤버 체크박스 선택 시 해당 멤버의 선택 상태를 토글한다.
- `내보내기` 또는 `멤버 초대` 버튼을 통해 멤버 목록 반출 또는 초대 흐름으로 진입한다.

### 제약사항

- 멤버별 권한은 프로젝트 단위로 관리돼야 하며 권한 없는 사용자는 멤버 정보를 수정할 수 없어야 한다.
- 멤버 초대, 삭제, 권한 변경 이력은 수행자와 변경 시각을 포함해 추적 가능해야 한다.
- 동일 사용자는 하나의 프로젝트 안에서 중복 멤버로 등록될 수 없어야 한다.

## 3. 대시보드 > 설정 (DA-M03)

- 업무 레벨 1: 대시보드
- 업무 레벨 2: 설정
- 화면 유형: 탭 화면
- 화면 ID: DA-M03
- 화면명: 설정
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: 대시보드 내 서비스 기본 정보를 관리하는 설정 탭이다.

### 화면 구성

- 진입 위치: 대시보드 상단 `Settings` 탭
- 설정 섹션: `General`
- 입력 항목: 서비스 표시 이름, 설명, URL
- 하단 버튼: `저장`, `취소`

### 처리절차

- 사용자가 대시보드 `Settings` 탭을 선택한다.
- 서비스 표시 이름, 설명, URL을 입력하거나 수정한다.
- `저장` 버튼 클릭 시 입력한 기본 정보를 저장한다.
- `취소` 버튼 클릭 시 저장하지 않고 변경 흐름을 종료한다.

### 제약사항

- 서비스 표시 이름과 URL은 프로젝트 또는 조직 내에서 식별 가능한 값이어야 한다.
- URL은 유효한 형식으로 관리돼야 하며 잘못된 주소가 저장되지 않아야 한다.
- 설정 정보는 권한 있는 사용자만 조회/수정할 수 있어야 한다.
- 설정 변경 이력은 변경자, 변경 시각, 변경 항목을 기준으로 추적 가능해야 한다.

## 4. 시나리오 > 시나리오 리스트 (SCA-M01)

- 업무 레벨 1: 시나리오
- 업무 레벨 2: 시나리오 리스트
- 화면 유형: 메인 화면
- 화면 ID: SCA-M01
- 화면명: 시나리오 리스트
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: TS/TC/TV 트리와 시나리오 그룹, 버전, 파일, 관리봇을 한 화면에서 관리한다.

### 화면 구성

- 상단 기능: 목록/그래프 보기 전환, `Files`, `코드 변경 탐지`
- 좌측 버전 타임라인: 변경 감지 버전, 일반 버전, 즐겨찾기 표시
- 메인 리스트: TS/TC/TV 트리, 체크박스, 검색, CSV, 변경사항 필터, 보류 항목, TS 추가
- TS/TC/TV 행: 확장/접기, 수정, 추가, 삭제, 선택, 상태 표시
- TC 행: 연관 FR 배지 및 hover 툴팁
- TV 행: API method/path, request JSON, status code, 검증 조건
- 우측 패널: 시나리오 그룹 검색, 그룹 카드, 그룹 필터, 예약하기, 실행, 그룹 생성
- 테스트 예약 팝업: 예약 날짜, 예약 시간, 반복 옵션, 예약/취소 버튼
- 하단 시나리오 관리봇: 대화 히스토리, 빠른 요청 칩, 컨텍스트 태그, 메시지 입력

### 처리절차

- 사용자가 좌측 내비게이션에서 `시나리오`를 선택하면 TS/TC/TV 트리 목록을 표시한다.
- 검색어 입력 시 TS ID/명 기준으로 목록을 필터링한다.
- 변경사항 필터를 선택하면 AI 변경 항목만 표시한다.
- AI 변경 항목에서 `승인`, `보류`, `거절`을 선택하면 해당 상태로 목록 표시를 갱신한다.
- TS/TC/TV의 추가, 수정, 삭제 아이콘을 선택하면 화면 상태를 즉시 갱신한다.
- TC/TV 체크박스를 선택하면 우측 그룹 생성 버튼이 활성화된다.
- 그래프 보기로 전환하면 중앙에 TS 흐름 그래프를 표시하고 노드 선택 상태를 연동한다.
- 우측 그룹 카드를 선택하면 해당 그룹에 포함된 시나리오만 필터링한다.
- 그룹 카드의 `예약하기` 클릭 시 테스트 예약 팝업을 표시하고 예약 날짜, 시간, 반복 조건을 입력한다.
- 그룹 카드의 `실행` 클릭 시 진행중 테스트를 생성하고 테스트 리스트의 진행중 상세로 이동한다.
- 하단 관리봇에 메시지를 입력하면 AI 응답과 신규 시나리오 초안을 추가한다.

### 제약사항

- 시나리오, 테스트케이스, 테스트변수 간 계층 관계가 일관돼야 한다.
- 변경 이력과 버전 정보는 파일/코드/사용자 입력 출처를 구분해 저장해야 한다.
- TS/TC/TV 삭제 시 하위 항목, 그룹, RTM 연결 영향 범위를 사용자에게 명확히 알려야 한다.
- 시나리오 그룹에 포함된 TC/TV는 원본 시나리오 버전과 추적 가능해야 한다.
- 승인, 보류, 거절 처리된 AI 변경 항목은 처리자와 처리 시각을 남겨야 한다.

## 5. 시나리오 > 시나리오 그룹 생성 popup (SCA-P01)

- 업무 레벨 1: 시나리오
- 업무 레벨 2: 시나리오 그룹 생성
- 화면 유형: 팝업
- 화면 ID: SCA-P01
- 화면명: 시나리오 그룹 생성 popup
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: 선택한 TC를 기준으로 시나리오 그룹 생성 전 선택 내역을 확인한다.

### 화면 구성

- 호출 위치: SCA-M01 우측 패널
- 팝업명: `시나리오 그룹 생성`
- 표시 항목: 선택된 TC 개수, 선택된 TC 목록
- TC 목록 정보: TS ID, TS명, TC ID, TC명
- 버튼: `생성 확인`, `취소`

### 처리절차

- 사용자가 시나리오 리스트에서 TC/TV를 선택한다.
- 선택 항목이 있으면 우측 패널의 그룹 생성 버튼이 활성화된다.
- 그룹 생성 버튼 클릭 시 팝업을 표시한다.
- `생성 확인` 클릭 시 선택 항목 기준으로 테스트 실행 항목을 생성하고 테스트 리스트의 진행중 상세로 이동한다.
- `취소` 클릭 시 선택 항목은 유지한 채 팝업만 닫는다.

### 제약사항

- 그룹 생성 대상 TC는 하나 이상의 항목이 선택돼야 한다.
- 동일 그룹 내 TC는 중복 포함될 수 없어야 한다.
- 그룹 생성 시 선택된 TC의 소속 TS와 기준 시나리오 버전을 함께 저장해야 한다.
- 그룹명은 프로젝트 내에서 식별 가능해야 하며 빈 값으로 저장될 수 없어야 한다.

## 6. 시나리오 > 파일 첨부/업데이트 popup (SCA-P02)

- 업무 레벨 1: 시나리오
- 업무 레벨 2: 파일 첨부/업데이트
- 화면 유형: 팝업
- 화면 ID: SCA-P02
- 화면명: 파일 첨부/업데이트 popup
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: 시나리오와 연결된 파일 목록과 반영 상태를 확인하고 수정 요청으로 이어간다.

### 화면 구성

- 호출 위치: SCA-M01 상단 우측 `Files` 버튼
- 팝업 구성: 연결 파일 목록 `FileList`, 파일별 반영 상태
- 버튼: `닫기`, `수정 요청`

### 처리절차

- 사용자가 `Files` 버튼을 클릭하면 연결 파일 팝업을 표시한다.
- `닫기` 클릭 또는 팝업 외부 클릭 시 팝업을 닫는다.
- `수정 요청` 클릭 시 팝업을 닫고 하단 시나리오 관리봇을 연다.
- 수정 요청 시 관리봇 컨텍스트 태그를 `연관 파일 변경 반영`으로 설정한다.

### 제약사항

- 첨부 파일은 프로젝트와 시나리오 반영 대상 범위가 명확히 연결돼야 한다.
- 파일 업데이트 시 기존 파일 버전과 신규 파일 버전의 차이가 추적 가능해야 한다.
- 파일 반영 상태는 시나리오 생성/수정 이력과 연결돼야 한다.
- 허용된 파일 형식과 용량 정책을 벗어난 파일은 첨부할 수 없어야 한다.

## 7. 시나리오 > 시나리오 버전 분기 popup (SCA-P03)

- 업무 레벨 1: 시나리오
- 업무 레벨 2: 시나리오 버전 분기
- 화면 유형: 팝업
- 화면 ID: SCA-P03
- 화면명: 시나리오 버전 분기 popup
- 최종 변경일자: 2026-05-11
- 화면 한줄 설명: 변경 감지 버전에 대해 새 버전 분리 여부를 확인한다.

### 화면 구성

- 구현 형태: 별도 모달이 아닌 좌측 버전 타임라인 hover 팝업
- 표시 조건: 변경 감지 버전에 마우스 오버
- 표시 항목: `변경 감지`, 변경 설명, `버전을 분리할까요?`
- 버튼: `No`, `Yes`

### 처리절차

- 사용자가 변경 감지 버전에 마우스를 올리면 분기 팝업을 표시한다.
- `No` 클릭 시 팝업을 닫는다.
- `Yes` 클릭 시 팝업을 닫는다.

- 좌측 패널: RTM 버전 선택, CSV 버튼, 전체 PASS율 도넛, 요약 건수, FR 목록
- RTM 버전 드롭다운: 버전 라벨, 날짜, 기반 문서
- FR 목록: FR ID, 충족/미충족/미측정 상태, 요구사항 요약, 요구사항별 mini donut
- 우측 패널: 선택 FR 헤더, TC 실행 이력 테이블
- 테이블 컬럼: TS, TC, 최신실행 이력 ID, 최근테스트자, PASS/FAIL

### 처리절차

- 사용자가 좌측 내비게이션에서 `RTM`을 선택하면 첫 번째 FR을 기본 선택한다.
- RTM 버전 드롭다운을 클릭하면 버전 목록을 표시한다.
- 버전을 선택하면 선택 버전 라벨을 갱신하고 드롭다운을 닫는다.
- FR 목록에서 항목을 클릭하면 우측 헤더와 실행 이력 테이블을 갱신한다.
- 선택 FR에 이력이 없으면 빈 상태 문구를 표시한다.

### 제약사항

- FR, TS, TC 간 추적성 매핑은 누락 없이 유지돼야 한다.
- RTM 충족/미충족/미측정 상태는 최신 실행 이력 기준으로 산정돼야 한다.
- RTM 버전별 요구사항과 테스트 매핑은 독립적으로 보존돼야 한다.
- CSV 내보내기 시 화면의 선택 버전과 필터 기준이 동일하게 적용돼야 한다.
